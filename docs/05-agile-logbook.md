## 5.3 Stand-ups, Communication and Coordination

The team used Microsoft Teams for meetings and WhatsApp when Teams experienced technical problems.

Weekly progress presentations to the lecturer formed part of the project process. However, internal communication was sometimes inconsistent, and meetings did not always take place weekly.

GitHub was used to share code through branches and commits, while Trello was used to track tasks and backlog activities.

These tools supported communication and coordination, although the team could have improved the consistency of internal updates and task tracking.

## 5.5 Project Retrospective

### What went well

-   The team identified a practical student-marketplace problem and presented the proposed idea for approval.
-   Figma supported discussion and review of the intended interface before frontend implementation.
-   Responsibilities were distributed across frontend/UI, backend/database, documentation and coordination.
-   GitHub, Trello, Teams, WhatsApp and Postman supported different aspects of collaboration and development.
-   The project progressed through development, system testing, lecturer presentations and deployment activities.

### What was challenging

-   Communication was not always consistent, and meetings did not always take place weekly.
-   Some project documentation and deployment information were difficult to obtain towards the end.
-   Backend security configuration and API troubleshooting were challenging for me.
-   I sometimes needed tutorials and AI assistance to investigate unfamiliar technical problems.
- The system currently's facing loading problems since it was deployed thorugh render
### What I learned

The project provided practical experience with Java, Spring Boot, Spring Security, REST APIs, Postman and database connectivity.

I also learned that software delivery depends on more than coding. Communication, documentation, testing, integration, task management and deployment are equally important parts of a software development project.

Another important lesson was that technical problems should be investigated systematically. Testing API requests and examining responses helped me understand backend behaviour and identify possible causes of errors.

### What I would improve next time

1.  Record meeting decisions, blockers and action owners consistently.
2.  Keep the product and sprint backlogs updated and connect tasks to commits and test evidence.
3.  Test frontend/backend integration earlier and repeat tests after changes.
4.  Confirm deployment ownership, URL, configuration and access before the final presentation.
5.  Practise coding and debugging without immediately relying on AI or tutorials, then use those resources to verify and strengthen my understanding.
6.  Maintain a more detailed development log with actual dates, activities, technical problems and resolutions whenever possible.
