## 5.5 Retrospective

### What went well

-   The team identified a practical student-marketplace problem and presented the idea for approval.
-   Figma supported discussion of the intended interface before frontend implementation.
-   Work was divided among frontend/UI, backend/database, documentation and coordination responsibilities.
-   GitHub, Trello, Teams/WhatsApp and Postman supported different parts of collaboration and development.
-   The project reached system testing, lecturer presentations and a deployment attempt.

### What was challenging

-   Communication was not always consistent, and meetings did not always take place weekly.
-   Some project documentation and deployment details were not readily available at the end.
-   Backend security and API troubleshooting were challenging for me and sometimes required tutorials or AI assistance.
-   The application is currently not accessible online, and the deployment details still need confirmation.

### What I learned

I learned more about implementing backend functionality with Java and Spring Boot, configuring security, working with REST APIs, testing with Postman and checking database connectivity. I also learned that software delivery depends on coordination, testing, documentation and deployment—not only on coding.

### What I would improve next time

1.  Record meeting decisions, blockers and action owners consistently.
2.  Keep the product and sprint backlogs updated and connect tasks to commits and test evidence.
3.  Test integration earlier and repeat tests after changes.
4.  Confirm deployment ownership, URL, configuration and access before the final presentation.
5.  Practise coding and debugging without immediately relying on AI or tutorials, then use those resources to check my understanding.
